# JRS-RG v1.6：研究动机、创新设计与完整实验方案

## 研究目标与当前进度

研究对象是多机器人施工中的质量恢复调度：返工改变作业区域的物理状态，原有验收依据可能失效，依赖这些依据的后继任务必须重新满足开工条件。需要共同决定返工对象与范围、重新验收的时机与覆盖范围、机器人分工和后继任务放行顺序。

v1.6 的核心目标：在接近 v1.5 的规划时间内，提高相对原始 JRS 的按期合格完成率，重点检验高失败率与紧截止期。当前交付完成新的决策内核、CUDA评估路径、22种方法配置、全部内部消融、配对统计、多GPU分片与绘图。性能是否达到目标，由独立实验结果判定。

现有环境是施工恢复的事件级仿真，包含机器人技能、空间影响、通道冲突、测量延迟、验收时效与后继任务。它尚不包含四道完整施工工艺的力学模型，也没有新增真实机器人数据。论文的工程描述应与这一实现范围一致。

## 三个工程问题，对应三个解决方案

| 宏观问题 | 工程困境 | 本版解决方案 | 要验证的结果 |
|---|---|---|---|
| 1. 物理作业与质量证据相互影响，任务依赖会随返工变化 | 一次局部返工可能撤销多个区域的验收依据，已经完成的后继作业也可能需要重做；只优化返工顺序无法描述完整代价 | **恢复依赖图**：把移动、返工、拍摄、测量交付、后继执行表示为有向图节点；分别记录资源时序依赖和质量因果依赖；由受影响任务生成返工批次与范围候选 | 联合目标、批次、证据复用分别贡献多少完成率和J改善 |
| 2. 局部修复速度不能直接代表项目按期合格完成 | 修复失败会增加诊断和重试，验收延迟会推迟开工，紧截止期会放大这些时间损失 | **GPU批量随机完成时间传播**：对候选恢复图采样失败重试和次生损伤的时间储备，沿依赖图传播完成时间；直接以整回合按期合格完成概率为第一排序依据 | 高失败率和紧截止期的完成率是否提高；相同评估器下结构化候选是否优于随机候选 |
| 3. 动态执行中既要响应异常，也要避免频繁改计划 | 每个事件都重新规划增加计算；固定执行又可能在新缺陷或验收撤销后继续沿用过时安排 | **事件驱动的局部计划续接**：执行所选恢复链的可行前沿，短阶段复用批次结构；发现新增修复任务、后继撤销、失败状态回退或截止期压力时重新搜索 | 完成率能否保持或提高，同时减少搜索次数与端到端规划时间；固定续接和每步重规划各有什么代价 |

可以用于论文动机的概括：**施工恢复的难点，在于返工同时改变物理质量、验收依据和后继作业的时间可行性。JRS-RG以恢复链作为调度单元，将这些变化统一映射为任务完成结果，再以事件驱动方式执行。**

## 与现有调度架构的具体差异

这里描述本仓库中可运行方法的决策差异，不把这些实现称作外部论文作者代码。

| 架构 | 主要决策单元 | 如何处理验收与后继任务 | 本版新增的内容 |
|---|---|---|---|
| QA顺序 / 检查优先 | 单个动作与优先级 | 执行过程中按规则安排检查和后继任务 | 在动作执行前比较完整恢复链的完成结果 |
| 保守局部 / 全部重置 | 影响范围与证据清除规则 | 使用局部保守范围或清除全部证据 | 在统一质量要求下优化保留证据的调度价值 |
| 重叠批次 | 空间影响重叠的返工集合 | 依照重叠关系合并返工 | 同时考虑依赖任务、交付时间、机器人资源和截止期 |
| 原始JRS | 返工批次与重新验收联合规划 | 使用共同的确定性预报，已有后继任务和证据撤销建模 | **原始JRS已经是联合方法**；v1.6进一步引入随机图传播与事件续接，不能把“首次联合返工与验收”作为新增贡献 |
| v1.5 | 学习代理评分与收益门控、短期续接 | 对原有方案评估收益并决定是否切换 | 新核心直接生成、评估和执行恢复图；无需训练v1.5代理，v1.5只作为冻结速度与效果对照 |
| JRS-RG | 恢复链的图结构及可行前沿 | 联合时间传播、证据有效性和异常触发重规划 | 检验结构化搜索、随机完成评估与事件执行的联合贡献 |

建议提出的三个算法贡献是“恢复图的候选组织与双依赖表示”“面向按期合格完成的批量随机评估”“事件触发的恢复链执行”。它们是本版待验证的研究贡献；其相对文献的新颖性仍需针对具体论文逐项核对，不能仅凭本仓库对照宣称首创。

## 算法细节与实现对应

### 1. 恢复图

每个候选包含返工分组和首组作用范围。候选族包含全部返工、先检查再返工、逐项返工、面向受影响任务的分组、单个返工前缀、重叠连通分组及扩大修复范围。

图中两类边分开维护：

- `deps`：必须先完成的资源、通道、空间冲突和工序事件。
- `quality_deps`：某次后继执行实际依赖的验收和返工证据。

这样，一个不相关返工的失败不会仅因为共享机器人、排在同一资源队列中，就被算作另一个任务的质量失败。测量拍摄与结果交付分成两个节点，防止把“已经拍摄”当作“已经获得验收依据”。

候选构造采用受影响任务的超边表达；可计算的执行计划是有向无环图。机器人分配和视点选择使用确定性启发式。因此这是受限候选搜索，不是全局最优解算法。

### 2. GPU随机完成时间评估

对候选 c、样本 s、图节点 v，完成时间递推为：

`F[c,s,v] = max(release[c,v], max(F[c,s,u] for u in predecessors[v])) + D[c,s,v]`

候选与样本两个维度并行；图的前驱关系按拓扑顺序传播。CUDA通过Torch执行持续时间采样后的张量运算与传播，仿真环境、图编译和合法动作打包仍在CPU。

随机时长模型包括有上限的几何失败重试、重试前诊断耗时、次生损伤的一轮修复与复检时间储备。它是公开信息下的快速近似，并未复制真实环境隐藏状态，也不是完整物理蒙特卡洛仿真。当前次生损伤储备不显式展开后续修复的全部资源冲突和多代传播；预测偏差须结合逐决策记录分析。

同一语义事件使用共同随机数，减少候选之间因抽样不同产生的评分波动。

完整方法按以下顺序选择候选：

1. 最大化预测整回合按期合格完成率；
2. 最大化预测合格完成任务比例；
3. 最小化预测成本；
4. 最小化预测完成时间P90。

预测成本用于候选排序；最终报告的J完全由原环境计算。预测储备并不等价于真实返工次数，不能混报为实测成本。

### 3. 事件执行

选择后保留批次结构，最多续接2次可执行前沿。每次续接仍用当前公开观测重建时序并通过共同合法动作接口。正常证据变化不再一概触发重新搜索；新增修复任务、后继撤销、失败状态回退和截止期压力触发重规划。若当前结构没有可执行动作，重新搜索。

`jrs_rg` 内核不调用原始JRS作为默认决策或回退；`baseline_policy_calls` 记录为0。保留轨迹审计、配置冻结与异常记录，是为了保证实验可复现，与算法决策中的收益门控是两件不同的事。

## 22种实验配置

### 横向比较：完整方法与8个对照

| ID | 方法 | 回答的问题 |
|---|---|---|
| jrs_rg | 完整JRS-RG | 主方法 |
| fixed_jrs | 原始JRS | 相对原有联合规划，完成率是否提高 |
| qa_sequential | QA顺序 | 是否优于逐项返工与验收 |
| robust_local | 保守局部 | 是否优于合理的局部保守处理 |
| whole_reset | 全部重置 | 复用未受影响证据是否有收益 |
| overlap_batch | 重叠批次 | 是否超越空间重叠合并 |
| independent | 检查优先 | 改善是否只是检查优先级产生 |
| fixed_random | 随机候选＋原确定性预报 | 相对原有搜索参照的收益 |
| jrs_release | 冻结v1.5 | 是否保持当前版本的规划速度 |

所有方法共享物理世界、可见观测、合法动作、质量要求、期限与测试种子。全部重置只改变公开证据处理策略，物理世界身份保持一致。此差异在配置和结果中显式记录。

### 全部内部消融：2×2×2全因子 + 6个结构对照

三个因素用J/U/E表示；此处J是“联合目标”因素标识，区别于成本指标J。

- J：联合恢复链的完成目标；关闭时仅按返工工作量和返工移动量选候选。执行仍必须合法检查与验收。
- U：随机失败与次生损伤时长；关闭时使用名义时长。
- E：事件驱动续接；关闭时每步重新搜索。

`jrs_rg_f000`至`jrs_rg_f111`覆盖8种组合。`f111`与完整方法相同，复用`jrs_rg`结果，不重复运行。单因素删除是f011、f101、f110；另外四种组合用于估计交互作用。

六个结构对照：

| ID | 改动 | 对应机制 |
|---|---|---|
| jrs_rg_no_batch | 只允许单个返工作为一组 | 批次组织 |
| jrs_rg_no_reuse | 全部证据重置 | 局部证据复用 |
| jrs_rg_serial | 串行安排和执行 | 多机器人并行 |
| jrs_rg_fixed_phase | 固定短阶段续接，不使用异常触发中断 | 自适应中断 |
| jrs_rg_no_temporal | 评估时移除主要前驱时序耦合，实际执行仍合法 | 时序模型价值 |
| jrs_rg_random | 随机分组候选，使用相同图编译器和随机评估器 | 结构化候选价值 |

总计：完整方法1 + 外部对照8 + 其余全因子7 + 结构对照6 = 22。

## 场景、样本与运行阶段

| 阶段 | 独立基础世界 | 条件 | 方法 | 回合数 | 用途 |
|---|---:|---:|---:|---:|---|
| smoke | 3 | 3 | 22 | 198 | 执行、配置与统计流程检查 |
| probe | 12 | 3 | 22 | 792 | 检查预测失配、机制贡献和GPU速度 |
| main | 600 | 5 | 22 | 66,000 | 冻结后的主实验与全部内部消融 |
| budget | 60 | 3 | 4 × 4种候选预算 | 2,880 | 实测计算投入与效能曲线 |

基础世界由随机种子生成，布局为hall、irregular、l_room。条件从同一个基础世界派生，保留几何、初始质量、机器人和任务身份。动作效果采用键控随机数；不同方法使用同一潜在随机世界，但因动作不同，不要求事件轨迹相同。

五个条件：

- base：次生损伤概率0.20，返工失败概率0，验收时效60。
- failure_high：实际及公开假设的返工失败概率均为0.15。
- deadline_tight：基准任务截止期乘0.65，物理时间范围保持100。
- collateral_off：实际及假设的次生损伤概率均为0。
- model_shift：实际次生损伤0.35、实际失败0.15；公开假设仍为base值，检验模型失配。

model_shift检验参数失配下的迁移；三个布局检验几何差异。不要把这些结果写成已验证新工艺、真实现场或任意任务规模的泛化。若要增加任务规模，应独立定义额外测试集。

smoke、probe、main、budget的世界标识与split分离。v1.6主方法没有学习训练阶段；v1.5代理模型冻结随包提供，仅供对照使用。

## 主验收：完成率第一，速度同时报告

拟定工程目标：failure_high和deadline_tight相对原始JRS各提高至少8个百分点；base完成率下降不超过3个百分点。规划时间目标：相对冻结v1.5的平均规划墙钟时间不超过1.2倍，决策P95不超过20ms。8pp、3pp和20ms是本次设计目标，不是已有结果或期刊规定。

`primary_acceptance.csv`输出配对完成差及三项主比较的同时区间。高失败率、紧截止期要求区间下界>0且点估计达到8pp；base要求区间下界>−3pp。速度结果写入`speed_acceptance.csv`，包括完整回合规划墙钟比及汇总决策P95。

600世界是预设主实验规模，不代表自动获得足够功效。冻结前使用开发集的配对不一致比例估算功效：当目标差δ=0.08、配对不一致比例q约0.35，正态近似样本量约为`(z_(1−0.05/6)+z_0.8)^2*(q−δ²)/δ²`，约560世界。base的3pp非劣检验可能需要更多样本；应在开发阶段一次性确定样本量，不能查看main后扩样直到显著。

各条件独立报告，不能把同一个基础世界派生的5个条件当作5个独立样本。主完成率配对比较使用世界分层bootstrap，同时报告全部对照的配对完成率检验和J差。全因子统计输出J/U/E主效应、两两交互和三阶交互，完成率与成本各自进行Holm校正。

主汇总表中的延迟来自整套运行，含实际主机负载。`benchmark_v16.py`额外执行预热后的CPU/CUDA评分一致性与评估器延迟测试，包含数据转换、传输和同步。GPU加速收益需要实测，不能用GPU利用率或候选数代替。

## 公平的计算预算比较

`run_budget_v16.py`设置候选上限4、8、16、32，比较完整方法、原始JRS、原确定性随机候选、同评估器随机候选。共享世界、条件与采样种子；报告实际规划墙钟和决策P95。

候选数相同并不等于计算量相同。论文画完成率—实测时间和J—实测时间曲线，展示相同时间量级下的表现。`benchmark_v16.py`的固定图测试只解释GPU评估器开销；不能代替端到端规划比较。

## 建议的执行顺序

先运行GPU smoke与CPU/CUDA一致性测试，再运行一次probe；依据probe定位实现错误与模型失配，确定配置后冻结main。main一次性覆盖全部22种方法，随后汇总、绘图和预算曲线，不再拆成多轮零散消融。
